# BTranslateVideo 说话人区分 语义断句与译文润色改进方案

设计稿 · 2026-11-22

断句同时考虑**谁在说、这一段话是否说完、是否进入了下一件事**。边界确定后，先核对译文有没有说清原意，再调整英语和日语的口语表达。首版通过现有校对和配音试听流程，让用户确认拆句、角色和润色建议。

## 当前流程与问题

Community-1 已提供支持重叠的说话人时间轴，以及同一时刻只保留一个标签的时间轴。项目按后者在整条字幕内的发言时长分配角色，再用前者检查重叠。假设 A 说了 3 秒、B 回了半秒「对」，即使模型找到了两人，A 仍占约 86%，超过当前 75% 的主角色占比阈值。在没有重叠和其他异常的情况下，这条可能直接建议给 A。 [角色匹配代码](../app/diarization.py#L111) · [Community-1 模型说明](https://huggingface.co/pyannote/speaker-diarization-community-1#exclusive-speaker-diarization)

B 站公开的原声翻译方案在细粒度语音上做说话人聚类，并加强少发言角色的识别。本项目首版借鉴的是**让换人边界进入台词切分**，用现有 Community-1 时间轴和 ASR 词级时间戳实现。 [B 站技术说明](https://www.bilibili.com/opus/1097484411804319809) · [ASR 缓存代码](../app/pipeline.py#L383)

现有语义断句会按窗口规划切点，校验原词是否完整，并尝试把同一说话人窗口末尾的最后一段留给下一窗口。代码虽然记录上一段文本并传入断句函数，实际发给模型的两种请求都没有包含这段上下文。模型能读到当前窗内的词，跨窗时仍可能把条件句截成半句，或把上一主题的收尾接到下一主题开头。保留了所有原词，也可能出现这样的边界错误。 [模型请求](../app/segmentation.py#L275) · [窗口规划与提交](../app/segmentation.py#L330)

项目已有原文润色、局部重识别、译文润色、联合校对和等义精简。翻译提示已经要求保留条件、否定、指代和问句。自动语义审校当前主要由源文中的英文、日文触发词和长度触发，常见中文短条件句可能跳过审校。规则会检查缺失数字和问号，但保留「三次」无法证明「最多三次」仍译成了上限。「优化已有译文」会重新翻译并审校，批量候选的改动说明通常是通用文本，用户仍得逐句找出实际变化。 [现有校对操作](usage.md#批量字幕工作台) · [审校触发与流程](../app/translation_quality.py#L61) · [译文规则校验](../app/translation_checks.py#L175)

## 使用流程

1. 在「配音与情绪 → 自动区分说话人」运行识别。保留自动人数、固定人数和人数范围。结果显示「估计 3 位说话人 · 4 处建议拆句 · 2 处重叠或需核对」，数字按本次实际结果计算。
2. 角色卡显示名称、匹配台词数、参考音来源和试听入口。存在两个疑似相同角色时，用户可以将候选台词分配给已有角色。参考音缺失的角色可以绑定音色库，或上传自己的样本。
3. 「建议拆句」行展示原句和拆后的台词，每段标出角色与起止时间。点击进入现有波形与拆合句面板，预填候选切点，可分别回听切点两侧并手动微调。常规单角色分配仍可批量采用。 [现有波形与拆合句](../app/static/subtitle-tools.js#L76)
4. 已有译文的句子可以手动指定译文切点，也可以为拆开的子句生成参考译文。确认时同时展示原译文与完整的新译文。生成失败时保留原句，用户可以重试或手动完成。
5. 采用后，角色卡支持用各自的原声参考试听英、日语配音。参考音尚不可用的角色在配音前显示缺失原因及补齐入口，避免生成整片时才发现问题。

在「翻译与校对」复用现有原声回听和拆合句面板。增加「断句待核对」筛选，显示原来怎么切、建议怎么切、涉及哪些相邻句，便于逐组试听。现有项目可以选中一段上下文重新检查后采用，已经人工校对的内容须明确确认。 [现有校对流程](usage.md#在字幕校对页导出字幕)

## 语义断句与主题衔接

断句的单位是**一段在当前对话中可以理解的话**。条件和结论、原因和结果、列表引导与紧跟的内容、术语与修饰成分应尽量在同一个语义单元。独立的回答「好」「不用」可以是一句。说话人真的被打断或原视频截断时，保留话说到哪里，并给出回听提示。

| 输入情况 | 建议边界 |
| --- | --- |
| 「如果模型连续三次没有响应」停顿后接「就重启服务」 | 把条件和处理步骤放在同一个语义单元。停顿可用于显示时换行。 |
| 「重启后检查日志。接下来我们看显存占用」连续说出 | 在上一件事收尾和下一件事开头之间切开，即使停顿很短。 |
| 「如果模型连续三次……」还没说完，另一个人插话「先别重启」 | 按角色保留两段，标出前一句中断。 |
| 原声在讲日志，识别文本出现原音里没有的无关句 | 标为「疑似识别异常」并提供原声回听和局部重识别，切点建议本身保留原词。 |

1. **让断句模型同时看到边界两侧。** 每次请求包含待处理原词、有限的前文和后文、词级时间戳，以及可用的换人线索。前后文作为只读参考，模型只提交待处理区内的切点和标点。窗口末尾仍依赖后文的内容留到下一窗，避免因为到了批次边缘就提交半句。首版沿用现有模型，缓存键包含实际使用的前后文、换人线索和规划版本，确保重新检查时使用对应的计划。
2. **只对可疑边界做局部复核。** 检查条件与结果被分开、主题转折被吞并、明显短残句，以及纯粹由停顿撑出的边界。取相邻两三条或短时间区间，建议保留、移动、合并或拆分，并验证原词顺序、数字与术语、时间覆盖和角色约束。可靠的换人点优先保留。主题变化结合前一句是否收尾和后一句是否开启新内容判断，单个「然后」「接下来」只作为线索。复核仍不确定时，保留当前字幕并标记回听。 [现有边界校验](../app/segmentation.py#L52)
3. **译配保留完整语义，字幕按需要分行。** 先按完整语义单元翻译，再按停顿和可读长度决定字幕行。如果一段完整话必须跨多条字幕，后续可以保留共同的语义单元关联，供上下文翻译和对齐使用。首版沿用现有字幕数据结构，优先修正实际误切。若原文和原声吻合、只有译文偏离主题，走现有邻句上下文重译。 [翻译上下文](../app/translation_quality.py#L78)

## 原文校对 译文润色与配音表达

先确认原文和断句，再润色译文，最后处理配音时长。复用「翻译与校对」现有候选对比和「角色与配音」的单句试听，让同一处修改可以对照原声、旧译文和新译文。 [现有译文优化流程](usage.md#优化已有译文)

| 问题 | 处理方式 |
| --- | --- |
| 原文有同音错字、术语识别错误或疑似多识别了一句 | 先局部重识别并回听。只需调整标点或清理明显重复时，可以直接出原文润色候选。涉及人名、数字、否定或新事实的改动，显示差异并要求明确核对。 |
| 原文正确，但译文漏条件、错指代或偏到邻句主题 | 结合前后句、角色和术语表，按原文逐项审校。比如「最多重试三次」必须保留上限，不能写成 *at least three times*。改动说明指出具体错处及相应的原文短语。 |
| 译文准确，但说出来生硬 | 建议口语改写。英语检查语序、搭配和重读处，日语检查自然省略、敬语和句尾。称呼和语气以已确认的人物关系、原话及相邻台词为依据。比如「行吧，那我们先到这儿」可译为 *All right, let’s leave it there for now.* |
| 译文自然，但实际配音挤不进窗口 | 先看已有的对齐结果或单句试听。只对确实超时的片段提供等义短稿，优先压缩赘词及重复。展示旧稿、新稿和可用窗口，采纳前可用同一音色试听并比较实测时长。 |

1. **补上中译英和中译日容易漏判的风险。** 在现有自动审校中补查「只有……才」「除非」「最多」「未必」「并非都」等中文表达，以及跨句代词、称呼和术语突然变化。前后文用于判断指代与语气，待处理句的事实仍以本句原文为准。角色关系不明确时允许保留歧义。
2. **让模型说明改了哪一处以及理由。** 沿用现有逐句候选，增加可定位的修改依据，例如「修复上限」「统一术语」「改顺口语」「疑似原文错识」。展示候选对应的原文短语和必要的相邻句。数字、单位、固定术语可做规则复核。条件、因果、人物关系等由模型对照原文给出疑点，存疑时交给回听。结构检查通过的候选仍作为建议显示。
3. **把等义精简接到实际对齐问题上。** 首版在现有候选及单句试听内对比稿件，采用后仍用当前译文作为正式配音稿，继续沿用项目版本校验、快照和配音缓存。没有可用音频时明确显示「估算时长」。如果更短的稿件会丢信息，保留原有完整稿并继续按对齐报告处理。 [现有按估算时长精简](../app/translation_quality.py#L255) · [现有整片对齐处理](usage.md#整片对齐的常规与保底上限)

## 换人边界与台词匹配

| 识别结果 | 处理方式 |
| --- | --- |
| 字幕内只有一个可靠角色 | 沿用现有角色建议。 |
| 两个或更多角色先后说话，切点两侧各有可对应的词 | 提议在相邻词边界切分，每段带独立的角色和时间。即使主角色超过 75%，只要短接话有词和说话人证据，仍提出拆句。 |
| 模型给出短暂角色切换，但附近缺少对应词，或角色在同一个词内反复跳变 | 标出候选时间供回听。短回应漏转写时，可在现有校对流程中补录原文。 |
| 常规时间轴显示两人同时说话 | 显示重叠范围和涉及的角色，交给人工校对。单说话人时间轴只用于辅助定位，保留重叠证据。 |
| 导入字幕、历史项目缺词级缓存，或用户编辑后原文与缓存词序对不上 | 仍可提出换人时间并回听，由用户在波形面板选择文字切点。 |

用匹配原片的 ASR 缓存定位词。先验证原句文字与该窗口的缓存词序一致，再检查每个词与角色区间的重合情况。切点落在词间且两侧能独立归属时，生成结构化建议，包含原句编号、子句文本、起止时间、角色、依据和待核对原因。一条原句有多次可靠换人时，可预览多段，整条一起确认。存在重叠时保留对应时间范围，供用户核对。

拆分前后校验词序完整、子句文本非空、时间有效且位于原字幕范围内。把「模型明确分出两人」与「模型给出的文字切点足够可靠」分别判断。模型可能漏掉只有半秒的发言，后续用标注数据决定是否为这类片段增加复判。首版用候选预览观察准确性，再确定哪些条件适合自动应用。

## 角色音色和项目数据

- 角色识别与参考音可用性分别显示。沿用现有 3–10 秒、无其他已检测角色重叠的参考音窗口，优先复用用户已绑定的音色。试听发现串音或背景音乐时，可另选同一角色的独白。若该角色只有短接话而缺乏可用参考音，保留台词归属，界面显示需要补参考音。 [现有参考音选择](../app/project_roles.py#L9) · [多人配音参考音检查](../app/pipeline.py#L521)
- 候选方案绑定原片指纹、识别请求和字幕版本。采用时使用服务端生成的候选及已确认的编辑，校验原句内容、切点、角色以及要绑定的参考音文件。一次保存选中的拆句和角色分配。版本冲突时提示刷新，用户可保留尚未保存的编辑。 [现有识别与采用接口](../app/diarization_api.py#L26)
- 拆句沿用现有编号规则，保留第一段的原编号，其余段使用新编号。按拆句后的正文、译文、时间及角色更新人工标记和成片有效状态，并用现有快照保留采用前的版本。只重新翻译选择重译的子句，配音继续按实际文本、音色及配置复用可用的缓存。 [现有拆句规则](usage.md#在字幕校对页导出字幕) · [配音流程](../app/pipeline.py#L643)

## 验收与实施顺序

先标注一小批有代表性的中文片段，覆盖单人口播、双人轮流发言、三人且有人只说一两句、带 BGM 的对话和同时开口。用同一批素材比较现版与首版，记录**人数正确的片段数、分错角色的台词数、短接话找回数、拆句建议正确数及需手修的条数**。角色编号在比较前按人工标注对应，避免把 `A/B` 标签互换算成识别错误。试听同一批已采用建议的中文转英语、日语配音，检查换人处是否切到正确音色。

语义断句增加中文长口播、同一人连续换主题、ASR 词窗口恰好落在一句话中间的样本。分别记录**半句误切、跨主题误合并、真实短回应被吞并、每分钟人工修改次数**。人工对照原声判定原字幕边界，再对比英、日译文是否保留条件、否定、指代和原有主题。纯回归测试校验前后文确实进入两种断句请求、每个原词只提交一次、不同上下文使用各自缓存，以及局部修改只影响确认采用的字幕。

润色用同一批已核对的中文原文和边界，对比中译英、中译日的旧稿与候选，分别统计**含义误改、跨句术语或称呼不一致、人工接受的口语改写、配音实测超时**。对同一句配音使用相同角色音色和合成参数。试听时先核对意思，再判断自然程度和时间贴合。

| 验收用例 | 首版通过条件 |
| --- | --- |
| A 说 3 秒，B 回半秒，时间轴和词级缓存均包含 B | 给出明确拆句建议，采用后 B 的词归入 B，切点可回听。 |
| 同一人长停顿后说完条件句，随后快速换主题 | 条件和结果连贯，下一主题独立起句。改变计算窗口位置时，人工标注的关键边界保持一致。 |
| 口语省略、实际被打断、疑似 ASR 多识别 | 保留有语用意义的短回答，实际截断可回听，疑似错识不在断句时擅自补写。 |
| 原文「最多三次」，候选改成「至少三次」 | 即使数字相同，也应标出上下限改变，候选须回到修改环节。 |
| 英日语精简稿更短，但遗漏否定或条件 | 保留完整稿。确认等义的候选用同一音色试听，比较真实时长。 |
| 单人停顿、音乐起伏及真正的抢话 | 单人样本无错误换声。抢话显示为重叠，需确认的内容可定位。 |
| 已校对译文、无词缓存、参考音不足 | 已有译文可完整核对后采用。缺词缓存时仍能手动拆句。缺参考音时角色可见，补齐入口明确。 |
| 识别之后另一窗口已保存，或生成子句译文失败 | 当前项目保留原有效版本，用户能辨认失败原因并重试。 |

第一阶段让前后文进入断句请求，通过波形预览交付语义修正与换人拆句建议，并在现有润色入口补足中文语义风险和具体的改动依据。真实样本通过边界与语义验收后，第二阶段让可靠换人点参与新项目的自动断句，并把等义精简接到配音超时项。若评测仍发现大量短发言在模型时间轴中缺失，再对比原音与去伴奏人声的识别结果。 [现有语义断句入口](../app/segmentation.py#L330)
