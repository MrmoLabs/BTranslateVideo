## 优先调整项

### 1. P1：增加“只识别字幕”的任务目标

**界面已复现。** 当前导入只提供原语言和“课程 / 动漫”内容类型，没有区分“仅转写字幕 / 翻译字幕 / 完整译制”。中文方言项目识别后仍显示“中文 → 中文”“15 句待翻译”，后续固定走向角色、音色、配音和混音。

这会使只想得到中文字幕的人误以为还必须翻译或生成配音。原文 SRT 已经可以导出，问题主要在流程组织和提示。

建议：

- 导入时选择任务目标，之后也能切换。
- 仅转写模式以“识别 → 校对 → 导出字幕”为主流程，直接提供 SRT / TXT 出口。
- 同语种配音提供明确的“使用原文作为配音稿”操作，由用户决定是否保留方言表达、是否整理为普通话书面语。
- 原语言和目标语言相同，不能自动被理解为“不需要任何文本处理”；方言整理、同语种重配音仍是独立需求。

代码依据：`app/static/workflow.js:9`、`app/static/workflow.js:14`、`app/static/workflow-core.js:4`、`app/server.py:478`。

验收：仅转写项目完成识别后能直接校对与导出，不出现必需翻译、角色准备或配音的阻挡提示。

### 2. P1：区分“本次操作完成”和“整个项目完成”

**界面已复现，源码确认。** 测试项目只有原文字幕、没有译文与成片，项目卡片仍显示“已完成”。卡片状态来自最后一次任务的 `status`，而不是项目目标和产物。

建议卡片显示“原文已识别 / 字幕待校对 / 字幕可导出 / 配音已生成 / 成片可下载”等产物状态。最近任务是否成功单独显示，例如“最近操作：识别完成”。完成识别不应被描述成整个译制项目完成。

代码依据：`app/static/app.js:4`、`app/static/workspace.js:322`。

验收：只完成识别的译制项目不显示为成片完成；仅转写项目则可以在其目标产物就绪时正常完成。

### 3. P1：识别页展示实际使用的模型，并校验原语言

**界面已复现，源码确认。** 素材页看不到本次将使用的识别模型，也看不到已有字幕由哪个模型生成。需要先离开项目，到全局设置找 Fun-ASR。当前全局识别器已经是 Fun-ASR，导入对话框仍默认英语，且仍列出该 Nano 后端不支持的语言。

模型不支持的语言会由识别适配器拒绝，但不应等到视频已复制、音频已准备之后才让用户发现。此问题属于入口校验不足，不是声称这些语言会被模型正确识别。

建议：

- 素材页展示“下一次识别：Fun-ASR-Nano / 中文 / GPU / 热词数量”。
- 已有字幕另列“上次识别来源”，避免把当前设置误当成历史结果来源。
- 区分“用当前模型重新识别原声”和“复用识别结果重新断句”；执行前展示受影响的字幕、译文与配音。
- 按识别后端校验语言，提供川渝方言预设；不要把全局模型切换悄悄应用到已有字幕。

代码依据：`app/fun_asr.py:47`、`app/model_backends.py` 的 `transcribe`、`app/pipeline.py:335` 的识别缓存判断、导入对话框 `app/static/index.html`。

验收：用户在项目内即可确认接下来用什么识别；不兼容的语言在创建或提交任务前被说明。

### 4. P1：普通字幕草稿增加异常退出恢复

**源码确认，未故意强制退出实测。** 普通原文、译文和配音稿的编辑主要在 `state.rows`，离开时有未保存提醒。候选编辑和角色名称已经有本地持久草稿，但本轮未发现普通字幕正文有同等的持久恢复逻辑。

建议按项目和正文版本保存本地草稿，重新打开时显示“恢复草稿 / 使用已保存版本”，再配合 Ctrl+S 和最近保存时间。草稿恢复需要验证项目版本，不应自动覆盖另一窗口已保存的内容。

代码依据：`app/static/app.js:144`、`app/static/workspace.js` 的正文编辑处理；可复用 `app/static/subtitle-review.js:5` 的本地草稿思路。

验收：浏览器异常退出后能找回未保存正文；多窗口冲突时允许比较或另存，不自动覆盖。

### 5. P2：字幕工作区压缩头部，减少重复按钮

**布局实测。** 在 1440×900 下，第一条字幕的顶部约为文档第 843 像素；当前 444×1022 下约为第 1294 像素。每行有 8 个操作按钮。桌面首屏几乎没有完整台词，窄窗口还要先滚过多组说明和工具栏。

建议：

- 语言与切换策略收成一条摘要，“修改语言”时展开。
- 表格上方保留搜索、筛选、保存、导出；说明折叠为帮助。
- 未选中句子时收起大部分批量工具，选中后出现范围清楚的操作栏。
- 行内保留回听、编辑详情及最常用动作，其余放入更多菜单。
- 窄窗口以一条字幕卡片为核心，控制说明高度；桌面支持紧凑密度。

代码依据：`app/static/workflow.js`、`app/static/workspace.js:382`、`app/static/style.css` 的字幕工具栏与响应式规则。

验收：900 像素高的桌面窗口能在首屏看到多条完整字幕；窄窗口首屏能看到当前句或直接进入当前句的入口。

### 6. P2：时间显示保留小数，统一列表、详情与播放器

**界面已复现。** 第一条字幕实际是 0.18–0.54 秒，列表和详情标题均显示“0:00–0:00”，而精确值藏在展开后的时间输入框里。原声播放器已有百分之一秒格式，可统一使用。

建议编辑界面统一为 `00:00.18–00:00.54`，同时显示时长 `0.36 秒`。持续时间太短、重叠或长时间空隙可以做提示，不能为了好看擅自改动时间轴。

代码依据：`app/static/app.js:14`、`app/static/source-audio.js:17`、`app/static/workspace.js:382`。

验收：小于一秒的字幕不会被显示成零长度；显示与 SRT 时间戳对应。

### 7. P2：主操作根据缺少的条件引导

**界面已复现，源码确认。** 当前没有译文时，顶部仍突出“角色与配音 →”；进入配音页又提示回去完成翻译。没有生成配音时，配音页仍给出“混音与导出 →”，到导出页后再提示返回。

四个步骤继续允许自由浏览，但顶部主按钮应根据当前目标和准备情况显示“校对识别结果 / 翻译剩余 15 句 / 准备角色音色 / 生成配音 / 下载字幕”等具体动作，避免只按当前页顺序跳转。

代码依据：`app/static/workflow-core.js:4`、`app/static/workflow.js:33`。

验收：主按钮不会将用户送到一个只有“请返回上一页”提示的状态。

### 8. P2：模型准备状态分层，技术设置放入高级区

**界面及源码确认。** 顶部“本地模型已就绪”主要由文件存在或本机接口配置推导，并不代表模型已成功加载和推理；设置页则同时展示运行环境路径、模型目录、VAD、缓存修订等技术字段。

建议把状态明确分成“文件齐全 / 环境可用 / 模型已加载 / 最近试识别通过”。常用区以模型、语言、设备和热词为主，路径、Python、VAD、协议、修订标识放入高级区。提供短音频试识别，并解释首次加载和模型下载的区别。

不要求检查文件时偷偷加载大模型；昂贵操作仍由用户明确触发。

代码依据：`app/static/app.js:46`、`app/model_backends.py:94`、`app/model_backends.py:231`、`app/fun_asr.py:25`。

验收：只有文件检查通过时，不宣称推理能力已经验证；高级字段不妨碍普通用户开始识别。

## 后续能力建议

### 字幕校对

当前原声回听已支持变速、循环和前后文，应保留。下一步可加键盘连续回听、当前句高亮、按光标拆句、与下一句合并、波形微调及撤销。它们属于新能力建议，本轮没有验证其实施后的收益。

建议增加“未核对 / 已核对 / 存疑”的人工标记和筛选，特别适合方言、人名、数字与低清音频。没有校准过的模型分数不要展示成准确率或可信度百分比。

### 项目与资源管理

项目已有搜索、回收站和存储管理，音色已有归档，建议继续沿用。可补充识别器、输出类型和进度筛选，以及“有几句字幕 / 是否人工校对 / 是否有成片”的摘要。默认 `speaker_1` 只代表尚未区分的分组，可以显示“说话人尚未区分”，避免把默认角色数当成已识别人数。

有声书目前为空状态，本轮只检查了入口和引导，未评价真实多章节编辑、生成与合并的交互质量。

### 性能和维护

- 任务记录区分排队、首次加载、模型推理、字幕断句等耗时，记录模型和设备。当前测试项目的累计耗时包含验证脚本与状态修复过程，不能据此评价 Fun-ASR 速度。
- 前端多个模块包装同名全局函数，加载顺序和状态依赖较多。建议在后续功能修改时逐步集中项目编辑与任务状态，保留现有草稿、切项目和迟到响应回归，不建议为本次界面调整一次性重写框架。
- 已修复的残留任务状态不作为本轮新缺陷重复列出。后续继续检查“运行队列、项目状态、进度快照”一致性，并用实际页面验证按钮反馈。

## 建议实施顺序

1. 首轮：任务目标、识别模型与语言入口、项目状态、短句时间显示。直接改善本次川渝字幕使用路径。

## 实施与复验 — 2026-11-17

已处理上述 8 项主要问题：

1. 新建项目默认“仅识别字幕”，另可选“翻译字幕”与“完整译制配音”。项目内可切换目标，保留字幕、音色与输出；旧项目沿用完整译制目标。仅识别流程直接校对、导出 SRT/TXT，不运行翻译或 TTS。相同语言另提供显式的原文复制操作。
2. 项目卡片和项目头部按实际字幕与输出显示产物状态，最近任务状态另列；保存后的摘要也从当前内容计算。
3. 素材页分列下次识别配置与历史识别来源；可为当前项目设置识别器、语言、设备和热词，不修改全局配置。导入读取当前识别器，Fun-ASR 默认中文，不支持的语言在入口和服务端提前拒绝。
4. 重新断句仅复用原识别缓存；显式重新识别才调用当前识别器。替换结果前保留历史备份。缺失缓存时明确要求重新识别，不会悄悄更换模型。
5. 普通字幕草稿自动保存在当前浏览器，支持异常退出恢复、导出副本、放弃草稿及 Ctrl+S；项目版本不一致时禁止直接恢复覆盖。
6. 缩小字幕工作台头部和工具区，批量操作按选择显示；单句默认保留回听、详情、更多。保留原有回听、循环和变速。时间显示百分之一秒和时长，可切换紧凑/舒适密度。
7. 主按钮根据字幕、译文、角色准备和已有产物给出可执行的下一步；字幕目标完成后直接导出。
8. 区分文件准备、运行环境检查和最近推理记录。提供显式环境检查及前 10 秒试识别，试识别不替换原字幕；识别模型路径和独立 Python 等字段收进高级区。
