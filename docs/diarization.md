# 本地说话人识别（Community-1）

在“配音与情绪 → 自动区分说话人”中选择运行设备和人数，再开始识别。先保存当前字幕草稿；识别本身不会替换字幕角色、参考音或已生成成片。完成后，可试听候选角色的原片参考音、逐句听原声，选择要采用的句子及角色，再点击“采用所选分配”。

## 批量调整与角色命名

识别结果中可“按识别角色筛选”，一键选中全部筛选结果（跨页），或者选择“统一分配到”并点击“将筛选结果统一分配”。这只修改候选；“采用所选分配”才会保存。筛选仍按模型最初识别的角色分组，因此调整后不会突然消失。待核对句默认不勾选；统一分配会显式选中该筛选内的全部句子，包括待核对句，请先试听确认。

采用后，在“项目角色与音色”直接编辑名称并“保存名称”，例如旁白、老师、学生。改名保留内部角色编号、台词、音色与已生成音频，不使字幕校对候选失效。新增角色不设固定总数限制，不受自动识别人数 1～50 的参数限制；角色也可以暂时没有台词。

点击角色卡片“批量调整此角色台词”即可选中该角色全部台词并筛选显示，在多句配音工作台批量设置角色、情绪、强度，再“保存配音设置”。也可自行筛选后“选中全部筛选结果”；所选句子跨页保留，操作前查看已选数量，需要时“清空选择”。给角色应用音色会用于该角色的台词；改完分配或音色后重新生成配音和成片。

Community-1 本身不转写台词，也不理解或翻译语义；本项目由独立 ASR 识别文字，再将说话人时间轴与字幕匹配。它给的是说话人标记与发言时间，不是去掉其他人声后的独立音轨。

## 能力与边界

- 使用 [pyannote Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1)，识别“谁在何时说话”。CPU、CUDA GPU 均支持，自动模式优先 GPU。
- 人数可以自动估算、指定固定人数，或设置最少／最多人数，范围为 1～50。人数设置是模型约束，不保证一定正确。
- 用模型的 exclusive 时间轴匹配字幕，并用常规时间轴检查重叠。匹配按人声时长计算，不是身份或声纹置信度。没有人声、覆盖不足、一句跨多人、重叠较多时标为待核对，默认不勾选。
- 不自动拆改字幕文本或时间，不识别真实姓名，也不把重叠音轨分成独立干净人声。动漫中的相似声线、变声和音乐可能影响结果；跨人发言的字幕需要人工重新划分或分配。
- 候选参考音从非重叠的原片片段取 3～10 秒，可能含音乐；不足 3 秒时，需要上传或绑定音色。原角色、音色库绑定均保留，不会被猜测为新人物。

## 可选独立环境

默认安装不自动下载受限模型，也不改变已有识别／配音环境。在项目根目录运行：

```powershell
# 只安装独立环境，不下载模型
.\.venv\Scripts\python.exe scripts\prepare_diarization.py --runtime-only

# 没有 NVIDIA CUDA 的电脑
.\.venv\Scripts\python.exe scripts\prepare_diarization.py --runtime-only --device cpu
```

运行环境使用 Python 3.11，位于 `runtime/diarization-env`，与应用的 Python 3.12 环境独立。固定组合为 pyannote.audio 4.0.7、PyTorch/torchaudio 2.8.0，以及与 PyTorch 2.8 兼容的 TorchCodec 0.7.0。CUDA 版使用官方 cu128 包，需要相应驱动。准备脚本使用 pip 保留已安装的 CUDA 构建，TorchCodec Windows 轮子来自 PyPI。音频由应用的 FFmpeg 预处理为 16kHz 单声道 PCM，从内存传入模型，不依赖 TorchCodec 解码。

在“设置 → 背景与媒体工具”配置完整模型目录、独立 Python 路径（留空自动定位默认环境）和默认设备。识别弹窗可重新检查本地文件。独立环境的真实依赖与 CUDA 检查命令：

```powershell
.\runtime\diarization-env\Scripts\python.exe scripts\diarization_worker.py --check
```

## 模型访问与下载

Community-1 为 CC-BY-4.0 模型，但官方仓库要求先由用户本人接受访问条件。需要自行在[官方模型页](https://huggingface.co/pyannote/speaker-diarization-community-1)申请／确认访问，然后用有读取此仓库权限的 Hugging Face token 在本机交互式登录：

```powershell
.\.venv\Scripts\hf.exe auth login

# 已准备运行环境后，仅下载模型
.\.venv\Scripts\python.exe scripts\prepare_diarization.py --skip-runtime
```

`pip install pyannote.audio` 只安装运行库，不会下载 Community-1 权重。全局 Python 中的安装也不会自动替代本项目的独立环境。创建 token 后，在项目目录执行上面的 `hf auth login`，交互输入有读取模型权限的 token；询问加入 Git 凭据时可选择 `n`。可用 `.\.venv\Scripts\hf.exe auth whoami` 确认登录账号（不要把 token 作为命令参数）。

下载后打开“配音与情绪 → 自动区分说话人”，点击“重新检查文件”和“检查独立环境”；显示模型文件已准备且依赖通过后，即可选择设备和人数开始识别。

不要把 token 写入项目设置、代码、命令行参数、截图或日志，也不要发送到聊天中。网页登录和本机命令行登录是两件事。脚本只在下载阶段使用本机 Hugging Face 登录，不提交用户的视频或音频，也不会代替用户接受访问条件。

默认目录 `models/speaker-diarization-community-1` 必须是完整本地快照，包含 `config.yaml`、`segmentation/pytorch_model.bin`、`embedding/pytorch_model.bin`、`plda/plda.npz` 和 `plda/xvec_transform.npz`。也可将已有完整快照放到本机并在设置中指定目录。准备脚本记录下载修订号与文件哈希；权重、缓存和环境不进入 Git。

## 离线、进度与资源

推理进程从本地目录加载；设置 Hugging Face 离线模式、禁用 pyannote 遥测，并阻止网络 socket 连接。进度显示音频准备、模型加载、切分、声纹提取、聚类和参考音准备；只有模型提供已完成／总数时才显示该阶段百分比。模型不提供细分进度的阶段显示正在处理，不伪造进度。

GPU 推理与其他应用模型任务共用队列和 GPU 锁，开始前释放本应用的配音模型，避免争用显存；CPU 模式不释放已保温的配音模型。不会关闭 LM Studio 等其他程序的模型。取消会终止该任务的子进程；失败或取消保留已有角色、成片及上次成功的候选结果。

采用时检查字幕版本和原视频是否变化；旧项目与媒体先备份到 `history/`。只改变选中句子的角色，保留原文、译文、时间、情绪以及旧角色和音色。采用后需重新生成受影响的配音与成片。尚未采用的候选结果也保存在项目中，关闭弹窗后可再次查看。

## 验收范围

回归测试使用推理替身与真实音频，覆盖字幕匹配、多人／重叠／静音标记、人数参数、不同候选参考音、采用与版本冲突、旧音色保护、取消和离线参数。它们不替代真实 Community-1 权重的准确率和 GPU 推理验收；下载模型后还需用实际多人素材试听核对。


### 登录时连接超时

`httpx.ConnectTimeout / WinError 10060` 表示未能连接官方服务，并不表示 token 已被判定无效。Windows 的浏览器 PAC 不一定会供命令行 HTTP 客户端使用。如果本机代理可用，可在当前 PowerShell 窗口设置 `HTTPS_PROXY` 为实际 HTTP 代理地址，然后在同一窗口登录并运行准备脚本。不要照抄不适合自己电脑的端口，不要关闭证书验证，也不要向第三方镜像发送 Hugging Face token。关闭该终端后，临时环境变量即失效。


## Repeated analysis and role lifecycle / 重复识别与角色管理

重复识别先根据本项目已有的台词分配及原片参考音时间窗口，保守对应先前识别角色。匹配要求参考窗口的高覆盖，或双方占优的台词时间重叠，并执行一对一对应；模型的 `SPEAKER_00` 等标签和显示名称不作为人物身份。匹配成功时复用原角色 ID，保留自定义名称、音色库绑定和既有参考音。不确定的新组使用未占用的名称；采用前可以在分组筛选、批量分配或逐句下拉框中指定已有角色。结果仍须预览并明确采用，匹配不表示人脸或真实姓名识别。

角色卡片标题旁提供“删除角色”。未分配台词的角色可以直接删除；仍有台词时可选择“暂不分配角色（保留全部台词）”，或迁移到另一个已有角色。最后一个角色也能删除，台词保留为未分配，不会再显示成一个虚假的角色卡片。可在配音表格按“未分配角色”筛选后批量重新指定角色，分配完成后再配音。接收角色保留自己的音色，音色库预设独立保留。删除前备份，台词分配变更使旧配音和成片失效，底层音频缓存及备份文件保留。已有历史重名角色可用此功能合并，或编辑名称区分。创建和改名会拒绝经 Unicode、大小写和空白归一化后重复的名称。
